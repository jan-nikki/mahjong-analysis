# コンボ理論の数理・実戦検証仕様

## 目的

対リーチで切る牌の危険度を、未見牌から作れる局所待ち部品の数で比較する
「コンボ理論」を、次の二つに分けて検証する。

1. 数理検証
   - 局所2牌組、完成分解上の待ち解釈、固有の13枚手牌状態を区別する。
   - 単純コンボ和が何を数えているかを明確にする。
   - 包含排除または固有手牌全列挙により、重複と完成手牌への延長数を検査する。
   - 単純コンボ順位と固有手牌ベース順位の逆転が起こり得るかを検査する。
2. 実戦検証
   - 対リーチ一人の各打牌判断時点で、その時点までに観測可能だった情報だけから
     候補牌ごとの特徴量を作る。
   - 実際のリーチ者の待ちを正解ラベルにし、全候補牌を危険／非危険に分類する。
   - 筋・壁・巡目等の既存情報にコンボを追加したときの、予測上および
     意思決定上の**限界効用**を測る。

コンボ単独の相関だけをもって有効性を主張しない。危険度予測と押し引きEVを
別レイヤーにし、観測データから識別できる量とモデル仮定に依存する量を分ける。

## 先に固定する結論と検証可能な仮説

### 数理上の暫定結論

- 単純コンボ和は、固有の13枚聴牌手牌数でも放銃確率でもない。
- 同じ手牌が複数の局所部品、完成分解、和了牌の割当を持ち得るため、単純和には
  重複がある。
- 重複がなくても、各局所部品から合法な13枚聴牌手牌へ延長できる数は一定ではない。
  したがって、局所部品数の大小から固有手牌数の大小は一般には導けない。
- 単純コンボ順位と固有手牌順位の逆転は、縮約した一色手牌空間の全列挙に加え、
  実牌譜から再生した到達可能な34牌種の観測状態でも確認できた。したがって、
  四人麻雀の実局面全体にも順位保存則はない。
- ただし、実際の鳳凰卓の観測状態で順位逆転がどの程度起きるか、また単純コンボが
  良い近似になるかは別の経験的問題である。
- コンボ値は未見枚数の決定論的関数である。未見枚数とその局所配置を十分に持つ
  ベースラインに条件づければ、母集団上の追加情報量は0である。有限標本、モデルの
  表現力、正則化の下では、有用な要約特徴として改善を生む可能性は残る。

### 仮説

| ID | 検証可能な主張 | 主な検証量 |
|---|---|---|
| M1 | 縮約モデルの順位不一致が、到達可能な実局面でも生じる | 実局面状態の反転件数、Kendallのtau-b |
| M2 | 実際のリーチ手牌にも、同一待ち牌の局所部品または待ち解釈の重複がある | 重複手牌率、候補牌率、重複次数分布 |
| P1 | 単純コンボは、牌種・巡目だけの弱い基準より危険牌順位を改善する | 判断内concordance、AUC、log loss |
| P2 | 筋・壁等の通常ベースラインへ単純コンボを足した改善は、単独性能より小さい | `baseline + simple` と `baseline` の対応差 |

後述の人工反例と実牌譜反例により、M1のうち「到達可能な実局面に少なくとも1件の
順位不一致が存在する」は確認済みである。ただし、開発用先頭10判断は代表標本では
ないため、頻度、Kendallのtau-b、実用上の大きさは主解析まで結論を置かない。

## 数理定義

### 牌と未見枚数

赤5を通常5へ正規化した34牌種を `i = 1, ..., 34` とする。ある打牌判断時点
`d`、観測者 `a` について、牌種 `i` の可視枚数を `v_i(d, a)`、未見枚数を
次で定義する。

```text
u_i(d, a) = 4 - v_i(d, a)
```

可視枚数には次を1物理牌につき1回だけ含める。

- 観測者自身の現在の純手牌
- 全員の河
- 公開されたchi、pon、daiminkan、kakan、ankan
- その時点までに開かれたドラ表示牌

鳴かれた打牌は、MJAI上の`dahai.pai`と副露イベントの`pai`の両方に現れても二重に
数えない。副露イベントの`consumed`は副露者が手牌から出した牌であり、別の物理牌
として数える。相手3人の非公開手牌、王牌の非公開牌、山牌は含めない。

候補牌は判断前から観測者の手牌内にあるため、その1枚は既に `v_i` に含まれる。
候補を切った後としてさらに1枚を引いてはならない。

### 単純コンボ

数牌 `x = r s`（rank `r`、suit `s`）について、`x`を1枚加えると順子になる
局所2牌組の集合を `Q(x)` とする。具体的には、`x`を含む全ての同色連続3牌から
`x`を除いた2牌である。

```text
Q(7m) = {(5m, 6m), (6m, 8m), (8m, 9m)}
```

ユーザー提示の単純コンボ値を次で固定する。

```text
C_simple(x; u)
  = sum(u_a * u_b for (a, b) in Q(x))
    + choose(u_x, 2)
    + u_x
```

字牌では `Q(x)` は空集合である。`choose(3, 2) = 3` なので、残り3枚から
2枚を選ぶ双碰部品は3コンボと数える。

この値が数えるのは、未見牌プールから局所部品に使う物理牌を選ぶ方法の単純和で
ある。残りの手牌、聴牌の合法性、完成分解、河から推測される選択確率は含まない。

### 区別すべき三つの対象

1. 局所部品
   - 例: `56m`、`68m`、`89m`、`77m`、`7m`。
   - 未見牌プール内の物理牌選択を数える。
   - 13枚手牌に延長できるとは限らない。
2. 待ち解釈
   - 固有手牌 `H` に候補牌 `x` を加えた14枚について、完成分解と、追加した
     `x`をどの面子または雀頭へ割り当てるかを指定したもの。
   - 同じ`H, x`に複数の完成分解・割当・待ち形があり得る。
3. 固有手牌状態
   - 赤を正規化した13枚相当の牌種count vector `H = (h_1, ..., h_34)`。
   - `x`に複数の解釈があっても、危険事象 `x in W(H)` では1ケースと数える。

既存の`calculate_hand_waits()`は、固有手牌ごとの構造待ち集合`W(H)`と、
`wait_tile × hand_type × wait_shape`を保持する。これは正解ラベルの検証に使えるが、
同じ3項関係へ到達する複数の完成分解・割当は重複排除される。数理監査では必要に
応じて、重複排除前の解釈も別APIで列挙する。

### 重複の具体例

宣言牌打牌後の手牌を次とする。

```text
H = 123m 456m 789m 4556p
x = 5p
```

`5p`を加えると、追加牌を`456p`へ割り当てる嵌張解釈と、`55p`の雀頭へ
割り当てる単騎解釈が成立する。同じ固有手牌は危険事象としては1ケースだが、
待ち解釈は2件である。

また、`H`は局所的には`46p`、`55p`、単独の`5p`を含む。しかし追加牌を
`555p`へ割り当てると`46p`が残るため、双碰解釈は成立しない。局所部品の存在、
待ち解釈の存在、固有手牌の危険事象が同じでないことを直接示す人工ケースである。

### 固有手牌ベースの標本空間

判断時点の未見枚数 `u` と、リーチ者の公開済み暗槓 `F` を固定する。暗槓数を
`k`とすると、列挙する純手牌の物理枚数は `n = 13 - 3k` である。

```text
T(u, F) = {
  H:
    sum(h_i) = n,
    0 <= h_i <= u_i,
    calculate_hand_waits(H, F).wait_tiles is not empty
}
```

固有count vectorを各1件とする無加重値を次とする。

```text
N_unique(x; u, F)
  = sum(1[x in W(H)] for H in T(u, F))
```

物理的に区別される未見牌から相手の純手牌を一様に選ぶ組合せ事前分布では、
count vector `H` の重みは次になる。

```text
w(H; u) = product(choose(u_i, h_i) for i = 1, ..., 34)
```

主たる固有手牌ベース値は、無加重countではなく次の加重確率とする。

```text
P_unique(x; u, F)
  = sum(w(H; u) * 1[x in W(H)] for H in T(u, F))
    / sum(w(H; u) for H in T(u, F))
```

分母は同じ判断内の全候補牌で共通なので、順位だけなら加重分子を使える。
これは「未見牌から13枚相当を一様に配り、合法な聴牌であることに条件づけた」
組合せ事前分布である。リーチ者の河、宣言選択、打ち手傾向を条件づけた事後確率では
なく、その限界を結果に明記する。

### 包含排除

候補牌`x`の待ち解釈型`m`について、`A_m(x)`を「少なくとも1つの合法な完成分解で
`m`として`x`を待つ固有手牌」の集合とする。`m`は標準形の順子・双碰・単騎だけで
なく、七対子単騎、国士単面、国士13面を含む。標準形の局所部品だけを調べる比較と、
全hand typeを含む比較を別に出す。このとき全hand typeを含む固有手牌の危険集合は
次の和集合である。

```text
A(x) = union(A_m(x) for m)
```

実装では全候補牌について次を検査する。

```text
union(A_m(x) for every supported interpretation m)
  == {H in T(u, F): x in W(H)}
```

したがって加重固有手牌数は、重み付き包含排除で計算できる。

```text
weight(A(x))
  = sum(weight(A_m))
    - sum(weight(A_m intersect A_n))
    + sum(weight(A_m intersect A_n intersect A_l))
    - ...
```

ただし `u_a * u_b` 等の単純コンボ項は `weight(A_m)` ではない。これは局所2牌を
選ぶ数にすぎず、その部品を合法な聴牌手牌へ延長する残り牌の数を掛けていない。
よって、単純和へ交差項を引くだけでも一般には固有手牌数にならない。正確な方法は
次のいずれかである。

- 各`A_m`と全交差集合について、完成手牌への延長を含めて重み付きに数える。
- `T(u, F)`の固有手牌を列挙し、`x in W(H)`を1回だけ数える。
- 完成14枚count vectorを色・字牌ブロックで因数分解し、候補牌を除いた状態を
  hand type間で和集合にして、上の列挙と同じ集合を重複なく数える。

縮約空間では`T(u, F)`の直接全列挙を監査正本とする。通常の34牌種実局面は候補空間が
数十億件になるため、三つ目の因数分解計数を使用し、縮約空間の総当たりと実局面の
独立な待ち手牌逆生成に一致することを検査する。

## 順位逆転の反例

### 縮約空間の人工反例

予備検証として、牌種を`1m`〜`9m`だけに縮約し、次の未見枚数を固定した。

```text
u = (3, 1, 1, 1, 1, 1, 4, 4, 1)
     1m 2m 3m 4m 5m 6m 7m 8m 9m
```

`h_i <= u_i`かつ合計13枚の全count vectorを列挙し、既存の待ち判定で標準形または
七対子の聴牌となる手牌だけを残した。国士はこの縮約空間では成立しない。

単純コンボは次になる。

```text
C_simple(2m)
  = u_1m*u_3m + u_3m*u_4m + choose(u_2m, 2) + u_2m
  = 3*1 + 1*1 + 0 + 1
  = 5

C_simple(4m)
  = u_2m*u_3m + u_3m*u_5m + u_5m*u_6m
    + choose(u_4m, 2) + u_4m
  = 1 + 1 + 1 + 0 + 1
  = 4
```

一方、固有手牌全列挙は次になった。

| 候補牌 | 単純コンボ | 無加重固有手牌数 | 物理組合せ加重分子 |
|---|---:|---:|---:|
| `2m` | 5 | 39 | 265 |
| `4m` | 4 | 46 | 396 |

したがって単純コンボは`2m > 4m`とするが、無加重・加重の固有手牌ベースはともに
`2m < 4m`となる。これは実際の136牌局面を再現した事例ではなく、未見枚数合計も
17枚しかない。縮約標本空間内の順位保存への反例であって、到達可能な四人麻雀局面
全体への反例とはしない。

この件数は次の独立な二経路が完全一致することを必須テストにする。

1. `0 <= h_i <= u_i`、`sum(h_i)=13`のcount vectorを直接全列挙し、
   `calculate_hand_waits()`で待ちを判定する。
2. 4面子1雀頭および七対子の完成形を生成し、和了牌を1枚除いて固有手牌へ戻し、
   count vectorを重複排除する。

### 到達可能な実牌譜局面の反例

2020年の開発用パイロットで、次の鳳凰卓東南戦・東1局の判断を再生した。

```text
source: data/raw/2020/2020010100gm-00a9-0000-03aa14b0.mjson
kyoku_index: 0
start_kyoku: 展開後2行目
tsumo: event_index 63、展開後65行目、actor 2
dahai: event_index 64、展開後66行目
target riichi actor: 1
```

同じ判断時点の可視情報から作った34牌種の未見枚数`u`について、候補`5m`と`4s`は
次の値になった。

| 候補牌 | 単純コンボ | 無加重固有手牌数 | 物理組合せ加重分子 |
|---|---:|---:|---:|
| `5m` | 31 | 959,250 | 20,732,233,681 |
| `4s` | 28 | 970,360 | 21,183,786,818 |

単純コンボは`5m > 4s`とする一方、無加重・加重の固有手牌ベースはともに
`5m < 4s`である。両牌は実際にactor 2の純手牌にある合法候補であり、未見枚数は
実イベント列からobserver-safeに再生した。固有手牌数は次の独立な二経路で一致した。

1. 標準形・七対子・国士の完成14枚count vectorを色ブロックごとに因数分解し、
   候補牌を除いた13枚状態をhand type間で和集合にして計数する。
2. 順子・双碰・単騎の待ち部品に残り面子と雀頭を加え、七対子・国士も別生成して、
   13枚count vectorを直接重複排除する。

これでM1の存在部分は確認できた。ただし、パイロットの順位集計はソート順先頭10判断
だけの計算量確認であり、反転率の母集団推定には使わない。詳細は
`docs/validation/combo-theory-pilot.md`に記録する。

## 実戦データの対象

- データセット: `NikkeTryHard/tenhou-to-mjai` `v2.0.0`
- 期間: 2020年〜2025年
- 四人打ち鳳凰卓東南戦、`rule_code == "00a9"`、赤あり
- 東場のみ
- 成立したリーチに対して、その時点でリーチ者がちょうど1人の局面
- 判断者は対象リーチ者以外で、判断時点で自身が成立リーチ済みでない者

「対リーチ一人」は判断時点でaccepted riichiが1人という意味とする。後に二軒目が
入る局でも、二軒目の`reach_accepted`より前の判断は含める。二軒目成立後の判断は
初期分析から除外する。

### 判断レコード

1判断は、対象者が対象リーチ成立後に牌を切れる時点とする。通常ツモ後の特徴量
スナップショットは、自身がリーチを選ぶ可能性を含めて、`tsumo`適用後かつ自身の
`reach`または`dahai`より前に作る。実際に自身が追っかけリーチを選んだ場合も、
判断時点ではaccepted riichiが対象者1人なので主解析へ含める。

主解析は、対象者自身の通常`tsumo`から、直接`dahai`へ進む列、または同一actorの
`reach`を1件だけ挟んで宣言`dahai`へ進む列を対象とする。後者でも候補集合と特徴量は
`reach`前の状態から作る。chi・pon・kan直後の打牌は、喰い替えを含む合法候補生成の
検証後に感度分析へ追加する。判断開始時点で自身が成立リーチ済みで、ツモ切りしか
選べない判断は除外する。

巡目は次で定義する。

```text
decision_discard_number
  = 判断者がそれ以前に行ったdahai数 + 1
```

主な巡目binは指定どおり次とする。

- 1〜6
- 7〜9
- 10〜12
- 13以降

加えて、対象リーチ者の宣言打牌番号と、リーチ成立後に判断者へ回った判断回数を保存
する。鳴きで卓全体のツモ順が変わっても、主binの定義を変えない。

### 候補牌

危険度データでは、判断者の純手牌にある合法な正規化牌種を1候補1行とする。同じ
正規化牌を複数枚持っていても危険ラベルは同じなので1行へ重複排除する。

EVデータでは、通常5と赤5で自分の打点価値が異なるため、物理的な合法打牌actionを
別に保持し、危険度行へ正規化牌種で結合する。

各行のキーは最低限次を含む。

```text
game_id
kyoku_id
riichi_id
decision_id
observer_actor
target_actor
decision_event_index
decision_discard_number
candidate_tile_kind
```

同じリーチ手牌が複数判断・複数判断者に再利用されるため、学習分割と不確実性推定は
候補行単位で行わない。

### 正解ラベル

理論検証の主ラベルを次とする。

```text
y_wait = 1[candidate_tile_kind in actual_target_wait_tiles]
```

実戦上の副ラベルを次とする。

```text
y_ron_eligible
  = y_wait
    and target is not discard-furiten on any actual wait
    and target has not passed any actual wait after riichi
```

`y_wait`はコンボ理論が構造待ちを近似できるかを測る。`y_ron_eligible`は今切った
ときの合法なロン危険を測る。両者を混ぜない。

リーチ者の宣言後の通常ツモ切りでは待ちは変わらない。宣言後に暗槓がある場合は、
その時点の純手牌・固定面子から待ちを再計算し、宣言時の`wait_tiles`と一致することを
検査する。不一致は黙って除外せず、局IDとイベント位置を監査出力する。

正解ラベル作成にはリーチ者の非公開手牌を使うが、特徴量作成には一切渡さない。
`start_kyoku.tehais`から他家手牌を取り込むリークを防ぐため、特徴量APIは必ず
`observer_actor`を要求し、他家の初期手牌を変更しても特徴量が不変であることを
人工テストする。

## 比較する危険度特徴

### 単純コンボ系列

- `combo_simple_raw`: 上記`C_simple`
- `combo_simple_rank`: 同一判断内の順位。大きいほど危険
- `combo_simple_percentile`: 同一判断内のpercentile
- `combo_visibility_residual`: 牌種・rank別の初期構造期待値を引いた値
- 局所項別内訳
  - 各順子部品
  - 双碰項
  - 単騎項

生の和だけでなく内訳を保存し、どの項が信号または誤差を生んだか確認できるように
する。`rank`と`percentile`は他候補の種類とスコアにも依存するため、候補牌自身の
局所未見枚数だけの決定論的関数とは扱わない。

### 固有手牌系列

- `unique_state_count`: `N_unique`
- `unique_physical_weight`: `P_unique`の分子
- `unique_tenpai_probability`: `P_unique`
- 各候補牌について、待ち形・hand type別の手牌集合件数
- 複数集合の交差件数と、包含排除で消える重複量

34牌種の正確な固有手牌列挙を全判断へ適用する前に計算量を測る。初期段階では、
巡目bin・年・可視枚数patternで層化した実局面標本へ正確な列挙を行う。全件適用が
現実的でない場合、主解析で近似値を正確値と偽ってはならない。次の順に扱う。

1. 重複排除した正確列挙の高速化または動的計画法
2. 同じ`u, F`のmemoization
3. 正確列挙したaudit標本で誤差を測ったMonte Carlo近似

近似を使う場合は標準誤差、seed、サンプル数、正確列挙との差を保存する。

### 通常ベースライン

弱い基準から強い基準まで段階化する。

1. `tile_turn`
   - 候補牌の牌種、数牌rank／字牌、端牌・中張牌
   - 判断巡目、リーチ巡目、経過巡目
2. `conventional`
   - 現物
   - リーチ後に通った同牌
   - 筋の各方向と本数
   - 壁・ノーチャンス・ワンチャンス
   - 候補牌自身の可視枚数
   - リーチ者河の位置、宣言牌との関係
   - 対象者の親子、局・本場等の公開状態
3. `visibility_local_saturated`
   - 候補牌周辺の各`u_i`
   - 候補牌自身の`u_x`
   - 柔軟な非線形項と交互作用
4. `visibility_decision_saturated`
   - `visibility_local_saturated`の全情報
   - 同一判断の全候補牌集合
   - 全候補について`combo_simple_raw`と内訳を復元できる未見枚数

`combo_simple_raw`と項別内訳は候補牌周辺の`u`の決定論的関数なので、
`visibility_local_saturated`へ追加した改善は有限モデルに有用な特徴変換かどうかを
測る診断である。判断内rank／percentileの情報量を診断するときは、候補集合まで持つ
`visibility_decision_saturated`を比較対象にする。

## モデル比較

同一の学習器・分割・候補集合で次を比較する。

```text
simple only
unique only
tile_turn
conventional
conventional + simple
conventional + unique
conventional + simple + unique
visibility_local_saturated
visibility_local_saturated + simple raw/components
visibility_decision_saturated
visibility_decision_saturated + simple rank/percentile
visibility_decision_saturated + unique
```

第一モデルは説明可能なlogistic/GAM系とし、第二モデルは同じ入力で非線形性を扱える
強い学習器とする。学習器を変えた差を特徴量の差として報告しない。主比較の学習器、
ハイパーパラメータ、欠損処理、確率calibrationの扱いは2020〜2023年だけで固定し、
2024年validationでは変更しない。具体的な固定条件は
`combo-prediction-freeze.md`と`combo-2024-validation.md`を優先する。

生コンボの順位性能は学習なしでも測る。log lossとcalibrationを測るときは、生の
コンボ値を確率とみなさず、学習期間・検証期間だけで単調calibratorを学習する。

### 分割

- 開発パイロット
  - 2020〜2023年からgame単位で固定抽出する。
  - 可視牌、label、順位逆転、計算量を確認し、仕様変更に使用したgame IDを保存する。
  - 2025年にはパイロット、目視監査、閾値選択を一切行わない。
- 主解析
  - 学習: 2020〜2023年
  - 独立validation: 2024年。calibrationは診断のみで、補正や仕様変更に使わない。
  - 最終test: 2025年
- 年代差
  - 生スコアの順位指標は2020〜2025年の各年で直接算出する。
  - 学習を要する指標は2020年からのexpanding-window予測を使う。各予測年について、
    学習、ハイパーパラメータ選択、calibrationを全て前年以前のgameだけで完結させる。
  - 2020年だけはgame単位cross-fitを補助値として示し、out-of-timeと表記しない。

同一gameは必ず同じsplitへ置く。少なくとも`game_id`、`riichi_id`、`decision_id`を
跨いで候補行がtrainとtestへ分裂しないよう検査する。

## 評価指標

### 順位一致

二種類を分ける。

1. 数理順位一致
   - 同じ`u, F`の候補牌間で`C_simple`と`P_unique`の全非同順位pairを比較する。
   - 一致率、逆転率、tie率、Kendallのtau-bを出す。
2. 正解ラベル順位一致
   - 同一判断内の危険候補と非危険候補の全pairについて、危険候補を高く置けば1、
     tieなら0.5、逆なら0とする。
   - 判断ごとに平均してから全判断を平均する。

全候補が同じラベルの判断では順位性能を定義できないため除外し、除外数とcoverageを
必ず報告する。log lossとcalibrationには残す。

### 予測性能

- candidate-row pooled AUC
- 判断ごとのmacro AUC／pairwise concordance
- log loss
- Brier score
- calibration intercept、slope
- reliability curveとECE

候補数の多い判断が過大に重くならない主集計では、各行を
`1 / candidates_in_decision`で重みづけする。無加重micro値も補助で示す。

限界効用は必ず対応差で示す。

```text
delta_log_loss = log_loss(base + combo) - log_loss(base)
delta_auc      = auc(base + combo) - auc(base)
delta_brier    = brier(base + combo) - brier(base)
```

95%区間はgame単位の対応cluster bootstrapで求める。候補行を独立標本として通常の
標準誤差を計算しない。全体、年別、指定巡目bin別を出し、多重な探索的subgroupは
主結果と区別する。

### 早巡差の分解

全牌がほぼ未見でも、中央牌は順子部品が多く、端牌・字牌と生コンボ値が異なる。
したがって「7〜8巡目まではコンボ差がない」とは置かない。巡目別に次を分解する。

- 牌種・rankの構造差による分散
- 同じ牌種・rank内で可視枚数が作る分散
- `tile_turn`追加後のコンボ限界効用
- `conventional`追加後のコンボ限界効用

この分解により、早巡の単独AUCを「見え枚数情報の効果」と誤認しない。

## 押し引きEV

### 識別できる部分とできない部分

実際の相手待ちが分かるので、「今この候補牌を切れば構造上当たるか」は全候補に
反実仮想ラベルを付けられる。一方、当たらなかった後の自分の和了率、将来打点、
将来の放銃、他家行動は牌譜から全候補について観測できない。したがって危険ラベル
だけから完全な押し引きEVを実測したとは主張しない。

### EV評価の段階

1. 対象リーチ者への即時ロンrisk
   - 同向聴・同等の受入れを保つ候補集合内で、baseとbase+comboが選ぶ牌を比較する。
   - `y_ron_eligible`による対象リーチ者への即時ロン可能率、対象リーチ者だけを見た
     oracle最安全牌へのregretを測る。
2. 一手proxy EV
   - 各物理actionについて、打牌後の向聴数、受入れ、手牌打点proxy、親子、巡目、
     点棒状況から非放銃時継続価値`V_continue(a)`を別モデルで求める。
   - 危険度モデルの`p_ron(a)`と放銃損失`L(a)`を用いる。

```text
Q_hat(a)
  = (1 - p_ron(a)) * V_continue(a)
    - p_ron(a) * L(a)
```

ここで`p_ron`は対象リーチ者に対する確率である。`V_continue`を使う場合は「対象
リーチ者に今ロンされなかった条件下」の価値とし、他2家への即時放銃と将来結果を
評価モデル側に含む。初期解析でそれを実装しない場合は、EVではなく対象リーチ者への
即時risk評価と明記する。

方策を作る予測器と方策を採点する評価器を分離する。base方策とbase+combo方策が
選んだactionは、どちらも同じ`Q_eval(a)`へ渡す。即時損失評価にはactual waitと
furitenから作る共通labelを使い、proxy EVには固定した共通仮定または学習から独立した
評価モデルを使う。各方策自身の`p_ron`で自身を採点してはならない。

```text
same selected action => evaluated policy-value difference == 0
```

3. 感度分析
   - `L`と`V_continue`を複数の妥当な固定値・推定値で動かし、結論が逆転する境界を
     示す。
   - 将来価値モデルに依存するEVと、即時放銃ラベルだけの結果を別表にする。

比較量は次とする。

- baseとbase+comboのaction変更率
- 変更局面における危険ラベル改善率
- 共通`Q_eval`で採点したpolicy valueの対応差
- actual waitを使った即時損失oracle regret
- 巡目、向聴数、自分の打点帯、親子、点棒状況別の差

実牌譜の実選択を教師としたoff-policy評価は、未選択actionの将来結果がなくpositivityも
弱いため、初期主解析にしない。

## 必須検証

### 人工テスト

- `7m`の式が`u5*u6 + u6*u8 + u8*u9 + choose(u7,2) + u7`になる。
- `choose(3, 2) == 3`。
- 端牌、2・8、中央牌、字牌の`Q(x)`が正しい。
- 赤5を通常5へ正規化し、物理枚数は4枚を超えない。
- 鳴かれた打牌を可視牌台帳で二重計上しない。
- 自分の純手牌は全て可視、他家の純手牌は全て不可視である。
- 他家の隠し手だけを変更しても全特徴量が不変である。
- `123m 456m 789m 4556p`の`5p`が1固有手牌、複数解釈になる。
- 上記縮約反例の無加重件数`39 < 46`、加重分子`265 < 396`を二経路で再現する。
- 実牌譜反例の`5m`と`4s`について、因数分解計数と待ち手牌逆生成の状態数・重みが
  完全一致する。
- 全hand typeの`A_m`和集合が`x in W(H)`の固有手牌集合と一致する。
- 国士単面・国士13面が包含排除の被覆から落ちない。
- 全候補牌labelが既存`calculate_hand_waits()`の待ち集合と一致する。
- `tsumo -> reach -> dahai -> reach_accepted`の宣言打牌判断を抽出する。
- 槓直後の嶺上牌による打牌判断を通常ツモ判断へ混入させない。
- リーチ後暗槓前後の待ち集合不変を検査する。
- 現物、リーチ後に通った牌、furitenをイベント時点どおりに判定する。
- 1・9、4〜6、字牌について筋参照方向が正しく、現物判定が筋より優先される。
- 壁特徴から辺張方向を除き、両面方向ごとのノーチャンス／ワンチャンスを判定する。
- 特徴量スナップショットに現在の`dahai`以後のイベントが混入しない。
- 予測行を`1 / candidates_in_decision`で重みづけし、AUC・log loss・Brierと
  判断内concordanceの人工例を再現する。
- game-cluster bootstrapが同じseedで再現し、同質clusterの人工例でpoint差と一致する。
- 固定標本manifestの選択ハッシュ改変を検出し、2024年・2025年を開発抽出へ渡せない。
- 局所未見枚数saturated特徴から単純コンボの全積項・双碰・単騎項を再構成できる。
- 二つの方策が同じactionを選んだ場合、共通評価上のvalue差が0になる。

### 実牌譜監査

各年・巡目bin・危険／非危険・順位逆転あり／なしから局IDを層化抽出し、MJAI原本を
目視できる監査表を作る。最低限次を表示する。

- raw source path、`start_kyoku`行、判断event index
- 対象リーチ者と判断者
- 判断時点までの公開イベント
- 判断者手牌と合法候補
- 可視枚数、未見枚数、単純コンボ内訳
- 実際のリーチ手牌、待ち集合、wait details
- simple順位、unique順位、正解ラベル

検出例だけでなく、simpleとuniqueが一致した対照例、全候補非危険の例、現物例も確認
する。

## 出力表

最低限、次を全体・年別・巡目bin別に出す。

1. 母数
   - game、kyoku、riichi、decision、candidate行
   - label陽性率、順位評価可能decision率
2. 数理比較
   - simple/unique順位一致、逆転、tie、tau-b
   - 重複手牌率、解釈数分布、包含排除補正量
3. 単独性能
   - simple、unique、各baselineの順位指標とAUC
4. 限界効用
   - baselineからのAUC、log loss、Brier、calibrationの対応差
5. EV
   - action変更率、即時risk差、proxy EV差、感度境界

年別差は点推定だけでなく区間を示す。2020〜2025年を合算した結果だけで年代差なしと
結論しない。

## この仕様で主張しないこと

- 単純コンボ値そのものが放銃確率であるとは主張しない。
- 組合せ一様事前分布`P_unique`が、河を見た後の真の事後確率であるとは主張しない。
- AUC改善だけで押し引きEVが改善したとは主張しない。
- 対象リーチ者への非放銃を、残る2家を含む局全体の非放銃とはみなさない。
- 実際に選ばれた打牌の結果だけから、未選択打牌の将来EVを観測したとは主張しない。
- 後巡の相関増加を、既存情報に対する限界効用の増加と同一視しない。

最終的な実用判断は、`conventional + combo`のout-of-time差と、action変更局面の
即時risk・proxy EVを中心に行う。単独AUCや人工反例は、数理的な位置づけを決める
ための証拠であり、それだけで採用・棄却を決めない。
