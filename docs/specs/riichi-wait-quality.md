# 成立リーチの筋待ち含有率・好形率（追加指標）

既存 `riichi-wait-summary-v1` を上書きせず、同じ2009〜2025年、東場、
00a9・赤ありの成立リーチ10,706,714件を分母とする。
通常リーチだけでなくダブルリーチ・追っかけを含む。
元dataset・待ち判定・既存booleanの意味は変更しない。

## 筋待ちを含む率

保存済みformal `wait_details` に、次のどちらかが存在するrecordを1件と数える。

- `standard / ryanmen` 解釈が1つ以上。
- 同じ色の異なる2牌に `standard / tanki` 解釈があり、数の差が3または6。
  後者を本分析の「ノベタン系」と定義し、延長形・複合形も含む。

`2345` の2・5単騎は含める。`3455` は34＋55の両面解釈により含める。
`2255` の2・5シャンポンのみ、七対子の単騎、国士はこの条件だけでは含めない。
`1234444567m EEE` の1m・7m単騎も含める（4mは純手牌4枚で候補外）。
差3だけではこの延長ノベタンを見落とすため差6も対象とする。

標準形の単騎解釈は「待ち牌1枚を元手牌から除くと完成面子のみになる」ことを
意味する。同色3・6差の異なる単騎解釈は順子の組み替えに由来し、単に待ち牌の
数字が3離れているだけのシャンポンは除外される。
複数の解釈があってもrecordは一度だけ数える。
両面のみ／ノベタン系のみ／両方／どちらもなしの排他的内訳を保存する。
暗槓で自己所有4枚となるformal waitも形の判定では落とさない。

「筋待ちを含む率」は筋の実際の通過率や放銃率ではない。
別の単騎・シャンポン等との複合も許容するため、筋が必ず通るとは解釈しない。

## 好形率

宣言打牌後の純手牌とfixed meldの全物理牌を、赤5を通常5へ正規化して数える。
重複しない各formal wait tileについて `4 - 自己保有数` を合計し、5枚以上なら好形。
同一待ち牌の複数解釈を重複加算しない。自己保有5枚以上はエラーとする。
暗槓の4枚は控除し、形式上の5枚目待ちの枚数寄与は0。
合計0枚のrecordも分母に残す。

これは手牌ベースの理論的待ち枚数である。本人の河、他家の手牌・河、ドラ表示牌、
山残枚数、フリテンは考慮しない。実際の和了可能な残枚数ではない。
他の完成面子に待ち牌を使わない例では、2345は6枚、3455は6枚、2255は4枚。

## 集計・検証・保存

判定処理と集計処理を分離し人工手牌でテストする。既存dataset readerによる
DTO/schema検証を維持する。manifest記載の17年度だけを年度ごとstreamingし、
事前にcompressed size/SHA256を検証する。読込件数は年度別・全体で照合する。
各年度・exact宣言打牌番号・年度×打牌番号も同じ指標を保持する。
率の平均ではなく整数countの合算から全体の率を算出する。

既存正式baselineとはmanifest SHA256、record数、既存両面含有件数を
全体・年度・打牌番号・年度×打牌番号で照合し、不一致なら出力しない。
筋待ちと好形のクロス集計、待ち枚数分布も整数countで保存する。

新しい小さなJSONを `research/results/riichi-wait-quality-v1.json` に保存する。
既存正式baselineのgeneration/pointerは変更しない。
未コミットの追加コードで計算した場合はcleanと偽らず、base commitと実際に
使用したコード・本仕様のSHA256を記録する。コミットは自動では行わない。
